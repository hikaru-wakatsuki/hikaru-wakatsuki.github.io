📑 【完全確定版】ポートフォリオ 要件定義＆アーキテクチャ設計書
0. 前提技術スタック・システム要件
フレームワーク: Astro + React (TypeScript)

スタイリング: Tailwind CSS (ダークモード対応)

状態管理: React Context API (テーマ、言語、GUI/CLI間のイベントブリッジ)

思想: インフラエンジニア・42 Tokyo学生としてのバックボーンを体現する、アトミックで独立性の高いモジュール設計。

1. 画面レイアウト・可変2分割システム (Layout & Dynamic Resizing)
画面を上下に2分割するだけでなく、境界線をユーザーがドラッグして自由にサイズ変更できるインタラクティブな構造を実装する。

PC表示時（幅768px以上）：スプリット＆ドラッグ可変システム

画面を上下に分割し、その境界線に数ピクセル幅の「ドラッグ用バー（スプリッター）」を配置。

JavaScript（ドラッグ制御）: バーへの mousedown イベントを検知したらドラッグ開始フラグを立て、window 全体の mousemove イベントでマウスのY座標（clientY）をリアルタイムに監視。

clientY の位置に応じて、上半分（GUI）と下半分（CLI）の高さ（height: Xvh）を動的に計算し、CSSの変数（カスタムプロパティ）をリアルタイムに書き換えて滑らかに追従させる。

各エリアの内部は独立スクロール（overflow-y: auto）とし、ブラウザ全体のスクロールバーは非表示にする。

スマホ表示時（幅768px未満）：ボトムシート引き出しシステム

基本は「上半分（GUI）」のみを 100vh で表示。画面右下の【Terminal】ボタンをタップ、または画面下部から上へスワイプ（タッチイベント touchstart / touchmove）すると、下から「下半分（CLI）」がボトムシートのようにニュッと引き出される設計。

2. システムコントロール（言語・テーマ・データ基盤）
サイト全体の見た目とテキストを管理する、フロントエンドのコアロジック。AppStateContext で一元管理する。

ダーク・ライトモード切り替え (Theme System)

ロジック: <html> タグの属性（data-theme="dark" または "light"）をJSで動的に書き換える。初期状態は matchMedia でユーザーのOS設定（デフォルトはダーク）に自動追従。

カラーパレット連動:

DARK: 背景 #121212 / CLI背景 #050505 ＋ グリーン文字（#00FF66）

LIGHT: 背景 #FAFAFA / CLI背景 #F0F0F0 ＋ 漆黒文字（#1A1A1A / Macのクラシックターミナル風）。

日英マルチリンガル対応 (Localization)

テキストデータを en.json と jp.json に完全分離。Reactの状態（State）として保持し、右上の EN / JP ボタンを押した瞬間に、ページ全体をリロードすることなくテキストを一瞬で差し替える。CLIのログメッセージも連動して英語化する。

データ構造の分離

スキルやプロフィールなどのデータは、HTMLに直書きせず独立した「JSONオブジェクト配列」として保持。

3. 上半分：GUIエリア（4つのコンポーネント詳細）
直感的な見やすさを最優先し、各セクションをすっきりとしたカード形式で配置する。

① プロフィール（Profile）

マグネットリンク演出: GitHubやXなどのアイコンにマウスが近づいた（距離50px以内）のをJS（clientX/Y と要素の中心座標の計算）で検知。イージングをかけながら、カーソル方向へ最大20pxほど磁石のように滑らかに吸い付くように移動（transform: translate）させる。

② スキルセット（Skills）＆ ③ ポートフォリオ（Portfolio）

双方向タグ連動: 両コンポーネントに共通の技術タグを配置。

スキルタグをクリック ➔ 配列の filter() で、該当スキルを使ったポートフォリオカードだけに一瞬で絞り込み・再描画する。

ポートフォリオカード内のタグをクリック ➔ スキル詳細エリアへ scrollIntoView({ behavior: 'smooth' }) で自動スクロール。

GitHub API自動連携: 初期ロード時に GitHub API（/users/ユーザー名/repos）から非同期（async/await）でリポジトリを取得。topics に "portfolio" が含まれるリポジトリを自動抽出して動的にカードを生成。

動画・画像ホバー制御 (Hover Playback): 各カードに「スクリーンショット画像」と「デモ動画（mp4/GIF）」のエリアを確保。普段は静止画だが、カードに mouseenter したらJSで動画の .play() を実行して滑らかに再生。mouseleave で .pause() し、再生位置を先頭（.currentTime = 0）に戻す。

④ 連絡先フォーム（Contact）

アドレス隠蔽: HTML上に生のアドレスは記述せず、JavaScript内部に暗号化（base64等）して隠匿。

UXスクリプト: input イベントを監視し、正規表現（Regex）で形式をリアルタイムチェック（OKなら枠線が緑、NGなら赤に変化）。送信中はボタンを disabled にし、成功時は画面端に「送信完了」のトースト通知を3秒間フェードインさせる。

4. 下半分：CLIエリア ＆ 拡張AIチャットボット (CLI & AI Engine)
バックボーンを体現する、GUIと100%同期して動くコマンドライン画面。

起動時タイピング演出

画面ロード（DOMContentLoaded）をトリガーに、システム起動ログ風テキストを setInterval（30ms間隔）で1文字ずつ擬似ターミナルに挿入出力する。

GUI連動ログ出力 (Event Bridge)

上半分のカードやタグへの mouseenter（ホバー）をグローバル（Context等）に監視。

ホバーされた要素のIDを検知した瞬間、下半分のターミナルが自動で改行され、$ cat [ファイル名] ➔ [Loading...] ➔ [概要文] を自動タイピング出力する。

AIチャットボットによる画面自動操作

ターミナルに $ ask "質問" と打ち込むか、専用チャット窓から入力しAPI経由でLLMへ送信。

返ってきたテキストを解析し、制御タグ（例: [CMD: SHOW_PORTFOLIO]）を検知したらJSのカスタムイベントを発火。上半分のGUIが該当位置へ自動スクロールし、同時に下半分のCLIに自動コマンド（$ list --portfolio 等）を走らせて画面全体を同期操作する。

6. AIエージェント向け 並列開発ルール（重要）
このプロジェクトは複数のAIセッションで並列開発（マルチスレッド処理）を行っている。
AIエージェントは指示された 指定のディレクトリ内のみ を編集対象とすること。他のディレクトリのファイルを修正したり、未完成の他コンポーネントに強く依存するコードを書かないこと。コンポーネントは単体で（モックデータ等を用いて）独立稼働する状態に仕上げるのが絶対条件である。
